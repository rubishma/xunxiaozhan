# 多目标管理第二小步：删除与编号保护

## 本轮目的

学习按编号删除资源，核对操作范围，并理解删除与暂停的区别。
本轮修改数据库操作、后端接口、页面和测试，新增本文并更新 README。
不增加依赖，不自动删除运行数据库中的任何目标。

## 从点击到删除

页面核对选中目标的编号、名称与网址 → 用户确认 → DELETE /api/targets/{id}。
后端查找目标并使用该目标的锁；正在检查或修改时返回 409。
数据库按编号删除一条记录，成功后返回 200 和 deleted_id。
页面收到成功响应后移除对应列表项和本页结果，选择剩余的第一个目标。
删除最后一条后显示空状态并展开添加表单。
取消确认不会发送删除请求。未保存的编辑需要先保存或取消，才能删除。

删除不会停止被监控的网站服务。暂停则保留目标配置，并拒绝检查。
不存在或已删除编号返回 404，旧页面应刷新；不会回退到操作其他目标。
网络中断时可能已删除但响应未到达，先刷新列表核对。
页面确认用于避免误点，不是后端鉴权；接口仍限本机或可信内网使用。

## 为什么新增编号记录表

仅依靠普通 SQLite INTEGER PRIMARY KEY 自动分配编号，删除最高编号后，
后续插入可能复用它。旧页面仍持有该编号时，就可能操作到新建的另一目标。
本轮新增 target_id_sequence，初始化时记录当前最大编号。
添加时，在同一个写事务中递增编号并插入目标；删除不会减少已分配的最大编号。
重启不会重置编号；旧 targets 表的编号、名称、网址和暂停状态保持不变。
不要手动清空编号记录表；当前仍只支持单个应用进程写入数据库。
目标锁保留到进程结束，适用于当前小规模学习版本，重启后重新建立。

## 验证记录

新增测试使用独立临时数据库和本机测试网站，覆盖：
- 删除指定目标不会影响同名目标，也不会请求目标网站。
- 重复删除、旧编号检查和修改被拒绝；同网址重新添加得到新编号。
- 删除最后一个目标后重启保持空列表，重新添加不复用旧编号。
- 旧表升级保留非连续编号、名称、网址及暂停状态。
- 检查中的目标不能删除，不同目标可删除，并发删除只成功一次。

## 学习与岗位能力

- 学会：按唯一编号操作，区分暂停和删除，识别 200、404、409 对应的操作结果。
- 运维或 IT 支持能力：变更前核对对象，变更后验证影响范围，通过日志定位原因。
- 独立操作：新增练习目标，取消一次删除，再确认删除；验证原目标仍可检查；重新添加核对编号。
- 面试问题：删除了编号 3 后，为什么不把 3 分配给下一个新目标？
