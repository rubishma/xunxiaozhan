# 近期检查耗时图

## 本轮目标

把已有检查历史画成图，帮助观察某次异常与前后采样的耗时差异。
新增 app/static/response-chart.js 与可选浏览器测试，修改页面、静态文件接口及原有接口测试。
没有增加依赖或修改数据库结构，继续复用 GET /api/targets/{id}/history 的最近 20 条记录。

## 如何读图

- 横轴：检查开始时间，按实际时间间距绘制，从左到右为早到晚，页面使用北京时间。
- 纵轴：本次检查耗时，单位毫秒，从零开始自动调整上限。
- 蓝色圆点：最终 HTTP 200–299 的正常结果。
- 红色菱形：异常结果；连接失败的耗时表示等到失败花了多久，并不是正常响应速度。
- 连线：仅连接相邻、正常且检查网址相同的数据点。失败与网址变更处断线。
- 详情：点击、悬停、Tab 选点或 Enter/空格，读取该次时间、耗时、状态码、来源、网址和原因。

一个点也能显示，零耗时仍是有效数值；无记录、加载中、读取失败与无效数据分别提示。
页面尺寸变化会重新计算坐标，保留选点详情，文字不会随整张图缩小。
图表与历史使用同一批数据；选择目标、完成手动检查或刷新历史时更新。
绘图脚本不发起网络请求，刷新只读取历史与事件，后台调度仍独立工作。
切换目标沿用现有请求编号保护，旧请求不能覆盖新目标。

## 边界

最近 20 条不等于全部历史，更早数据仍在数据库中。
失败不能画成零耗时，也不能与正常响应混为同一条速度曲线。
连线只连接采样，不证明两次采样之间一直正常；暂停和后端停止期间没有观测。
横轴短标签只显示时分秒，跨日期时应查看选点的完整日期。
修改网址不会改写旧点，点击可核对当时网址。

## 学习者操作

1. 在 8000 后端终端按 Ctrl+C，重新执行原 uvicorn 启动命令，刷新浏览器。
2. 选择原来的目标编号，找到“近期检查耗时”，核对点数与最近历史一致（最多 20 条）。
3. 点击正常点与失败点，对照下方历史的时间、耗时、状态码和错误原因。
4. 若最近 20 条全是正常记录，只停止 8765 测试网站，再点一次“立即检查”；
   随后启动 8765 并再检查一次，观察红色菱形与断线。保持 8000 后端运行。
5. 点“刷新历史与事件”，观察图表更新；暂停目标后仍能查看图表。定时任务可能独立新增记录。
