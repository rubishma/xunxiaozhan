# 定时巡检与重复执行保护

## 目的

让后端在浏览器关闭时也能按间隔巡检，把结果保存到已有历史中。
使用 Python 标准库的异步循环与文件锁，不安装新依赖。
新增 scheduler.py 和 process_lock.py，修改检查入口、历史来源字段与页面，补充配置和测试。
启动新版时所有未暂停目标都会被调度；本轮没有启动用户运行实例或自动更改暂停状态。

## 执行规则

- 默认间隔 60 秒，可配置为 30–86400 秒整数，配置错误阻止启动。
- 启动、新增、恢复巡检或保存配置后等待一个间隔。新目标从后台发现时开始计时。
- 完成一次检查后再等待一个间隔；手动检查也会推迟下一次定时检查。
- 暂停目标跳过，不产生检查记录；恢复不会补查暂停期间的数据。
- 同目标共用一个锁，手动检查与定时检查不能重叠；定时执行前再核对暂停和到期状态。
- 定时目标串行处理，适用于少量网站，慢目标可能让其他到期目标延后。
- 单次请求总时限仍为 10 秒；数据库操作在线程中执行，等待网络不会阻塞页面接口。
- 单目标报错不会终止循环；记录日志，在后续间隔尝试，不集中补跑错过的次数。
- 日程使用单调计时器，历史检查开始时间仍用 UTC 保存、北京时间展示。

## 生命周期和进程保护

FastAPI 启动时取得同一数据库对应的文件锁，然后初始化数据库和后台任务。
同一数据库的第二个进程无法取得锁，会启动失败；即使换端口，也不能重复运行同一数据库。
只使用 --workers 1，不使用 --reload；旧版应用没有这项保护，升级前必须先停止旧版。
文件锁是操作系统管理的锁，不是根据文件是否存在判断。锁文件应保留，不能手动删除。
进程异常退出后操作系统会释放锁；测试已覆盖 Windows 上强制终止持锁测试进程的情况。
Unix 分支使用标准库 fcntl，但尚未在 Linux 实机验证。仅支持本地磁盘，未验证网络文件系统。

正常停止时先阻止新定时任务，等待正在进行的检查完成，再关闭客户端和释放锁。
网络请求有总超时，数据库操作也有锁等待超时；若强制终止，仍可能丢失在途检查。
关闭浏览器只关闭页面，不停止后端；关闭后端、关闭电脑或电脑休眠会影响巡检。
重启后重新等待间隔，不补跑停机期间任务。目前没有开机自启和后台服务守护。

## 历史和页面

checks 表增加 source 字段，旧记录标为 manual（旧版本只支持手动），原记录不覆盖。
新记录区分 manual / scheduled，页面显示“手动”/“定时”。
顶部显示启动时读取的调度状态和间隔，这不是持续健康检测。
“刷新历史”只查询已保存记录，不触发检查；页面暂不自动轮询。
GET /api/scheduler 返回任务是否存活及间隔，不代表巡检全部成功或数据库健康。
配置方法见 README 和 .env.example；环境变量只在当前 PowerShell 会话设置。
