# 第二阶段第一小步：目标配置与持久化

## 本次学习目的

理解三件不同的事：在输入框打字、把配置保存到后端、请求网站取得检查结果。
当前只持久保存一个目标的名称和网址，不保存检查历史。

## 数据流

页面填写名称和网址
→ PUT /api/target
→ 后端校验输入
→ SQLite 事务保存
→ 页面显示已保存
→ POST /api/check
→ 后端读取已保存的网址
→ HTTPX 发起请求
→ 页面展示本次结果。

GET /api/target 在页面加载时读取配置。
数据库实际位置为项目根目录下 data/xunxiaozhan.sqlite3。
数据不依赖浏览器 localStorage，也不只存在 Python 的内存变量里。

## 对应的运维与 IT 支持能力

- 区分运行进程、程序代码和持久化数据。
- 用重启实验确认配置是否真正保存。
- 区分输入错误、保存失败与目标不可访问。
- 知道版本库不等于运行数据库备份。

自动测试使用独立临时目录，不修改运行数据库。
