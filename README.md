# 巡小站

AI 辅助开发的个人学习项目，用于练习 HTTP 服务部署、巡检与故障排查。
当前为第一阶段学习版本，还不是完成版监控系统。

## 本轮功能

- 页面手动检查固定目标 http://127.0.0.1:8765/。
- 显示正常、异常、尚未检查，以及状态码、请求耗时、检查时间和错误原因。
- 总时限 10 秒，跟随最多 5 次重定向，最终 200–299 为正常。
- 只读取响应头；失败耗时表示等到失败的时间。
- 验证 HTTPS 证书；网络客户端不自动读取系统代理环境变量。
- 异步请求；同一进程中的重叠检查返回 409。
- 采用 UTC 传输检查时间，页面显示北京时间。

目前没有目标编辑、暂停、数据库、定时检查、故障事件、曲线或鉴权。
页面刷新即丢失结果；不跟踪网站正文或业务流程。
证书错误目前与其他连接错误归在同一类，后续细分并测试。
只允许单进程启动；进程间重复启动防护将在定时任务阶段实现。

## 文件与职责

- app/main.py：FastAPI 接口、HTTPX 请求和重复检查保护。
- app/static/index.html：页面、样式和按钮逻辑，无外部前端依赖。
- requirements.txt：当前环境的完整依赖版本。
- tests/test_manual_check.py：通过本机可控服务验证行为。

## 环境

开发环境为 Windows、Python 3.13.15。其他操作系统尚未验证。
已有环境只需运行下面的启动命令；新环境先执行：

~~~powershell
python -m venv .venv
& '.\.venv\Scripts\python.exe' -m pip install -r requirements.txt
~~~

这里的 python 必须是已确认的 Python 3.13；多版本机器建议使用完整解释器路径。

## 启动

在项目根目录打开第一个 PowerShell 窗口，启动被检查的网站：

~~~powershell
& '.\.venv\Scripts\python.exe' -m http.server 8765 --bind 127.0.0.1 --directory app/static
~~~

这里只提供静态文件目录，避免将整个项目和虚拟环境作为测试网站内容公开。

再打开第二个 PowerShell 窗口，进入同一个项目目录并启动巡小站：

~~~powershell
& '.\.venv\Scripts\python.exe' -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
~~~

浏览器打开 http://127.0.0.1:8000/，点击“立即检查”。
8765 是被检查的网站，8000 是巡小站面板；操作面板只使用 8000 地址。
两个窗口都需要保持运行，按 Ctrl+C 停止对应服务。
此学习版本仅用于本机，不可直接暴露公网，不使用多 worker 或热重载。

## 故障演练

1. 两个服务均运行，点击检查，预期正常、HTTP 200。
2. 仅停止第一个窗口中的 8765 服务，再检查，预期异常、没有 HTTP 状态码。
3. 重新启动 8765 服务，再检查，预期恢复正常。
4. 如果停止的是 8000 后端，按钮请求会失败；这与目标网站异常不同。
5. /api/health 返回 ok 只说明巡小站接口可响应，不证明目标正常。

## 验证

~~~powershell
& '.\.venv\Scripts\python.exe' -m unittest discover -s tests -v
~~~

测试只访问临时本机服务，不依赖外部网站。
自动测试不等于浏览器和手机视觉验收，界面仍需手工检查。

## 常见问题

- 地址占用：日志若显示 WinError 10048，先确认是否重复启动了同一个服务。
- 找不到 app：确认终端处于项目根目录。
- No module named：确认使用项目 .venv 的 Python，并核对依赖安装结果。
- 页面能打开但检查失败：分别确认 8000 面板和 8765 目标的终端日志。
- 目标连接失败并不代表已确定原因；服务停止、地址错误等需逐项核验。
