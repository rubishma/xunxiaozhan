# 巡小站

AI 辅助开发的个人学习项目，用于练习 HTTP 服务部署、巡检与故障排查。
当前进度：多目标管理、手动与定时检查、历史持久化、故障事件合并、恢复记录、近期检查耗时图及本地备份恢复工具。

## 当前功能

- 添加多个目标，按编号选择、编辑名称与 HTTP/HTTPS 网址，配置保存到 SQLite。
- 按编号删除目标，页面确认后操作；检查中的目标返回 409，需完成后再删除。
- 删除不会关闭目标网站；新目标不会复用已删除编号，删除全部目标后重启仍为空列表。
- 相同网址经基本规范化后不能重复添加；同名但网址不同的目标用编号区分。
- 重启应用后保留配置和暂停状态；保存、暂停和恢复操作本身不会请求网站。
- 暂停时页面禁用检查按钮，后端也会拒绝直接检查请求。
- 手动和定时检查共用检查流程，显示正常、异常、尚未检查，以及状态码、耗时、时间和错误原因。
- 默认每次检查完成后等待 60 秒再定时检查；间隔可配为 30–86400 秒。
- 手动检查会推迟下次定时检查；暂停目标被跳过，历史标注“手动”或“定时”。
- 每次完成的检查保存到 SQLite，按目标显示最近一次结果和最近 20 条历史。
- 历史保留检查当时的名称和网址，修改配置不会改写旧记录；暂停不会清除历史。
- 首次失败建立故障事件，连续失败只增加同一事件的失败次数；首次检查恢复时记录恢复时间。
- 暂停保留未恢复事件；修改网址会将旧事件标为“网址变更而结束”，不算恢复。
- 最近 20 条历史绘制检查耗时图，正常圆点、异常菱形；点击、悬停或键盘选点查看详情。
- 图表按真实检查时间排列，失败或网址变更处断线，刷新图表不会发起网站检查。
- 命令行备份完整 SQLite 数据库、只读校验，并恢复到新文件；拒绝覆盖已有文件。
- 总时限 10 秒，最多跟随 5 次重定向，最终 200–299 为正常。
- 只读取最终响应头；失败耗时表示等到失败的时间。
- 验证 HTTPS 证书；HTTP 客户端不自动读取系统代理环境变量。
- 异步请求；SQLite 操作在线程中执行。
- 同一进程中，同一目标的检查与修改不能重叠；重叠请求返回 409。不同目标使用独立锁。
- 采用 UTC 传输检查开始时间，页面显示北京时间。

## 当前限制

暂未实现鉴权、通知告警或自动修复。
耗时图只展示最近 20 次采样，不代表连续可用性；失败耗时不能解释为正常响应速度。
事件时间表示检查发现异常或恢复的时间，不是实际故障发生和结束的精确时刻。
本功能启用前的检查历史不自动回填成事件；事件从新版首次失败检查开始记录。
后台独立执行定时检查，关闭浏览器不停止巡检；关闭后端或电脑则停止。
页面选择目标或点击“刷新历史”时读取记录，暂不自动刷新；最近结果只代表当时的状态。
后台串行处理到期目标，适合少量网站；目标多或响应慢时会延后，不保证精确每分钟执行。
尚未读取过的目标显示“选中后读取结果”，读取失败单独提示，不当成“尚未检查”。
历史接口只返回最近 20 条，数据库暂不自动清理，长期运行会持续占用磁盘；分页与保留策略后续完善。
升级前仅存在页面内存的结果无法补回；历史从新版第一次检查开始记录。
证书错误目前与其他连接错误归为一类，后续细分并专项测试。
同一数据库只允许一个应用进程，通过操作系统文件锁防止重复启动；只支持本机磁盘，未验证网络共享盘。
启动或重启后重新等待一个间隔，不补跑停止期间的检查；当前不提供开机自启或服务守护。
默认仅监听本机，不能直接暴露公网。只检查你有权访问和检查的目标。
本工具不验证网页正文、登录流程和全部业务功能。

## 文件与职责

- app/main.py：输入校验、FastAPI 接口与 HTTPX 检查。
- app/scheduler.py：计算下次执行时间，后台循环与停止处理。
- app/process_lock.py：阻止多个进程同时使用同一运行数据库。
- .env.example：检查间隔示例（不会自动加载，启动方法见下文）。
- app/backup.py：SQLite 快照备份、完整性与结构校验、恢复到新文件。
- tests/test_backup.py：临时数据库恢复、WAL、编号序列及拒绝覆盖测试。
- app/database.py：SQLite 初始化、旧表增量升级、目标配置、检查历史及故障事件读写。
- app/static/index.html：表单、状态展示、按钮逻辑，无外部前端依赖。
- app/static/response-chart.js：把已有历史绘制为 SVG 图表，无外部图表依赖。
- tests/test_response_chart.cjs：可选的本机 Edge 浏览器验证，使用明确标注的模拟数据。
- requirements.txt：已固定的完整依赖版本。
- tests/test_manual_check.py：本机服务和独立临时数据库测试。
- tests/test_scheduler.py：可控时钟、暂停、并发检查、异常恢复及跨进程锁测试。
- tests/test_incidents.py：持续故障合并、恢复、新故障、网址变更、暂停重启及事务回滚测试。
- data/xunxiaozhan.sqlite3：首次启动时自动创建的运行数据库，Git 忽略整个 data 目录。

## 环境与首次安装

开发环境为 Windows、Python 3.13.15；新增 Linux 容器运行方式，验证范围见第十阶段记录。
SQLite 使用 Python 自带模块，无需安装数据库软件。已有环境可跳过安装：

~~~powershell
python -m venv .venv
& '.\.venv\Scripts\python.exe' -m pip install -r requirements.txt
~~~

这里的 python 必须是已确认的 Python 3.13；多版本机器建议使用完整路径。

## 启动

在项目根目录打开第一个 PowerShell 窗口，启动被检查的网站：

~~~powershell
& '.\.venv\Scripts\python.exe' -m http.server 8765 --bind 127.0.0.1 --directory app/static
~~~

这里只提供静态文件目录，避免把项目配置和虚拟环境作为网站内容提供。

第二个 PowerShell 窗口进入同一个项目目录，启动巡小站：

~~~powershell
& '.\.venv\Scripts\python.exe' -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
~~~

浏览器打开 http://127.0.0.1:8000/。
8765 是目标网站，8000 是巡小站；操作面板只使用 8000 地址。
两个窗口都保持运行，Ctrl+C 停止对应服务。不使用多 worker 或热重载。
代码更新后，停止并重启 8000 后端，再刷新页面。

## 定时巡检配置与演练

默认间隔 60 秒，使用环境变量 XUN_CHECK_INTERVAL_SECONDS 设置 30–86400 的整数。
无效配置会阻止启动并给出错误，不会静默改用过短间隔。
.env.example 仅作配置说明，程序不自动读取 .env；在启动服务的 PowerShell 中显式设置：

~~~powershell
$env:XUN_CHECK_INTERVAL_SECONDS = '30'
& '.\.venv\Scripts\python.exe' -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
~~~

该变量只影响当前终端及其启动的进程，不修改系统环境配置。
恢复默认可在停止后执行 Remove-Item Env:XUN_CHECK_INTERVAL_SECONDS -ErrorAction SilentlyContinue，再启动。
变更间隔需要重启服务。第一次升级请先停止旧版后端，避免旧代码同时访问数据库。

- 启动后，未暂停的目标等待一个间隔再检查。新建目标从被后台发现时开始等待。
- 保存配置、恢复巡检会重置等待时间。每次手动或定时检查完成后也重新计时。
- 同目标正在检查时，手动请求返回 409，定时任务跳过本次机会；不同目标的手动检查仍可进行。
- 定时循环约每秒检查一次是否到期；机器休眠后恢复也不集中补跑旧任务。
- 保存失败会记入终端日志，下个间隔再尝试；历史读取不会触发目标网站请求。

本机练习：

1. 保持 8765 测试服务运行，以 30 秒间隔启动 8000。刷新页面，确认顶部显示 30 秒。
2. 选择 http://127.0.0.1:8765/ 对应目标，必要时恢复巡检；不点“立即检查”。
3. 等约 40 秒，点击“刷新历史”，应出现来源为“定时”的新记录。多目标故障时可能需要稍久。
4. 暂停该目标，记下最新记录时间；再等约 40 秒并刷新历史，不应新增该目标记录。
5. 恢复巡检后关闭浏览器，保持两个服务终端运行；约 40 秒后重新打开页面，应有新定时记录。

所有未暂停目标都会被调度。若只想练习一个目标，可先暂停其余目标。
后台会继续增加历史，练习结束后可停止 8000 后端。

## 多目标演练

1. 更新后重启 8000 后端并刷新页面；目标列表应保留原来的名称、网址和暂停状态。
2. 选择原目标，必要时恢复巡检；保持 8765 测试网站运行，手动检查首页，应得到 200。
3. 展开“添加目标”，名称填“本机404测试”，网址填 http://127.0.0.1:8765/missing-demo-page。
4. 添加成功后自动选择新目标，显示它自己的编号，结果为“尚未检查”。
5. 点击检查，应得到 404；这里是目标网站对不存在路径的正常 HTTP 响应，本项目按约定把非 2xx 判为异常。
6. 切回原目标，它仍应显示此前的 200。暂停新目标不应影响原目标。
7. 再次添加相同网址，应收到重复提示，不应多出一条记录。
8. 重启后刷新，两个目标都应保留；选中后会从数据库读取各自的最近结果。

编辑后有未保存的内容时，先保存或点击“取消修改”，再切换目标。
添加和删除目标都不会请求网站。删除演练见下一节。

## 删除演练

只对专门新增的练习目标操作，保留已有目标。

1. 重启 8000 后端并刷新页面；添加“删除练习”，网址为 http://127.0.0.1:8765/delete-demo。
2. 记下新目标编号。点击“删除目标”，核对确认框中的编号、名称和网址，先取消一次，记录应仍在。
3. 再次点击并确认，只有该目标应消失；选择原目标，仍可按原来的方式检查。
4. 用相同名称和网址重新添加，新编号应大于刚才删除的编号。

删除是移除数据库中的配置，暂停是保留配置并暂时不检查。
删除会在同一个事务中移除目标、全部检查历史和故障事件，确认框明确提示；没有撤销入口。
重新添加会分配新编号，不继承已删除目标的历史或事件。
删除最后一条后显示空状态，可重新添加；重启不会补回演示目标。
旧浏览器页面访问已删除编号会返回 404，请刷新列表；网络中断时先刷新核对是否已删除，再决定是否重试。
首次启动新版时，自动增加编号记录表，保留已有目标；编号记录不能随意清空。
仍只支持单进程，不能同时用旧代码写入同一数据库。

## 当前接口

接口已从单目标形式改为带编号的形式；旧版 /api/target 和 /api/check 不再使用。
历史阶段文档保留旧接口作为当时的学习记录，当前操作以本节为准。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | /response-chart.js | 加载图表脚本，不读取数据库或发起巡检 |
| GET | /api/scheduler | 读取调度任务是否存活及检查间隔，不代表目标健康 |
| GET | /api/targets | 读取所有目标 |
| POST | /api/targets | 添加一个目标，成功返回 201 |
| GET | /api/targets/{id} | 读取指定目标 |
| PUT | /api/targets/{id} | 保存指定目标的名称和网址 |
| DELETE | /api/targets/{id} | 删除指定目标，成功返回 200 和 deleted_id |
| PATCH | /api/targets/{id}/state | 暂停或恢复指定目标 |
| POST | /api/targets/{id}/check | 检查并保存结果，返回包含记录 id 的结果 |
| GET | /api/targets/{id}/history | 读取最近 20 条记录，按写入顺序从新到旧 |
| GET | /api/targets/{id}/incidents | 读取最近 20 次故障事件，新事件在前 |

不存在的编号返回 404，不会回退为检查第一个目标。
重复网址、暂停或同目标操作冲突返回 409；无效输入返回 422。
上述状态码是巡小站接口响应；目标网站自身的 HTTP 状态码在检查结果字段中。

## 目标配置与重启演练

1. 将名称改成“我的本机练习站”，保留 http://127.0.0.1:8765/。
2. 点击“保存配置”。页面提示保存成功后，点击“立即检查”。
3. 停止 8000 后端并重新启动，刷新浏览器；名称和网址应仍保留。
4. 选中目标后应显示重启前保存的结果和历史；没有保存过记录的目标才显示“尚未检查”。
5. 网址修改为 ftp://127.0.0.1:8765/ 后尝试保存，应提示无效；
   刷新页面后应读到之前保存的 HTTP 网址。
6. 同一个目标检查中不能修改配置；多窗口操作若收到 409，等检查完成再试。

名称限 1–80 字，网址限 2048 字符，只支持 HTTP/HTTPS，
不接受账号密码、空白或 # 片段。格式有效不代表网站一定能访问。

## 暂停与恢复演练

1. 重启 8000 后端并刷新页面，确认原来的名称和网址还在。
2. 点击“暂停巡检”，应显示“已暂停”，检查按钮禁用；目标网站本身不会被关闭。
3. 暂停后重启 8000 后端并刷新，暂停状态应保留。
4. 点击“恢复巡检”，等待一个间隔后后台会检查；也可点击“立即检查”获得新的目标状态。
5. 检查进行中不能暂停，接口返回 409，等待完成后重试；本轮不取消在途请求。
6. 暂停期间可以保存名称和网址，保存不会自动恢复巡检。

暂停表示主动不检查，不等于目标正常或异常。
下方读取的历史结果只代表之前那次检查，不能据此判断暂停期间网站的实际状态。
重启时自动为旧表添加 paused 字段，保留名称和网址，不要求删除数据库。
多进程并发升级尚不支持，请保持单进程运行。

## 检查历史演练

1. 重启 8000 后端并刷新页面，选择指向 http://127.0.0.1:8765/ 的目标，必要时恢复巡检。
2. 8765 测试服务运行时，点击一次检查，应新增正常、HTTP 200 的记录。
3. 只停止 8765 服务，再检查一次，应新增异常记录；没有收到响应，所以状态码为空。
4. 重新启动 8765，再检查一次，应新增正常、HTTP 200 的记录。
5. 刷新页面并重新选择同一编号，最近三条按新到旧显示：正常、异常、正常。
6. 停止并重启 8000，刷新并选择同一编号，记录及检查时间应保持；读取历史不会新增检查。

查看历史接口可直接打开 /api/targets/实际编号/history，存在但无记录返回 []，不存在返回 404。
所有检查开始时间用带时区的 UTC 字符串保存，页面固定显示北京时间。
更改目标名称或网址后，历史保留原始配置；最近结果若来自旧网址，页面会明确提醒。
检查历史每次检查一条；故障事件会合并连续失败。两者各展示最近 20 条，不删除更早数据。

## 故障事件演练

保持同一目标编号、同一网址，使用 http://127.0.0.1:8765/，不要用改网址代替停服务。

1. 重启 8000 后端、刷新页面，选择该目标；8765 运行时检查一次，应正常，且不会新建故障事件。
2. 只停止 8765，手动检查一次，查看“故障事件”：出现一条未恢复事件，记下事件编号。
3. 等本次检查完成，再检查一次：事件编号不变，失败检查次数增加。定时任务也可能增加次数。
4. 重启 8765，再检查一次；原事件应变为“已恢复”，保留首次异常时间，并新增恢复时间。
5. 再次正常检查不应创建事件，也不应改写首次恢复时间。

刷新按钮现为“刷新历史与事件”，只读取数据库，不会发起网站检查。
同一个目标连续失败不重复建事件；失败原因变化时更新最近失败原因，历史仍保留每次结果。
恢复后再次失败才建立下一次事件。故障只看最终 HTTP 结果，不以错误文本相同与否分组。
暂停不等于恢复：事件仍未恢复，页面提示巡检已暂停；恢复巡检后等新结果确定状态。
修改名称不结束事件。修改网址会结束旧网址未恢复的事件，end_reason 为 url_changed，recovered_at 仍为空。
检查历史和事件更新在同一个事务中提交；任一步失败都回滚，不产生半条更新。
不要用事件起止时间直接宣称真实停机时长，检查间隔及暂停期间都会造成观测空白。

## 近期检查耗时图

重启新版 8000 后端，刷新页面并选择目标，可在最近结果下方看到图表。
图表复用历史接口的最近 20 条记录，从左到右按检查时间排列；纵轴单位为毫秒。
正常结果用蓝色圆点，异常结果用红色菱形，异常耗时不补零。
只连接相邻、正常且网址相同的数据点，失败或网址变更处断线。
点击、悬停或用 Tab 选点，可查看该次时间、状态码、来源、实际网址及错误原因。
只含一个点、零耗时、全部失败或无记录均有对应显示；读取失败会提示，避免把错误画成空数据。
“刷新历史与事件”也会更新图表，只读取已保存记录；后台定时检查仍可能独立增加记录。
暂停期间没有采样，不能用正常点之间的连线证明期间一直正常；日期及完整信息见选点详情。
本轮没有修改数据库结构。练习步骤见 docs/stage-07-response-chart.md。

## 故障演练

1. 两个服务均运行，点击检查，应正常、HTTP 200。
2. 仅停止 8765 服务，再检查，应异常且没有 HTTP 状态码。
3. 重启 8765 服务，再检查，应恢复正常。
4. 停止 8000 后端则按钮无法获取新结果，与目标网站异常不同。
5. /api/health 返回 ok 只说明巡小站接口可响应，不证明目标或数据库健康。

## 数据库备份与恢复

代码的 Git 提交不包含 data 中的运行数据。完整演练见 [备份与恢复](docs/stage-08-backup-restore.md)。

~~~powershell
& '.\.venv\Scripts\python.exe' -m app.backup backup
~~~

成功后打印 backups 下的文件路径和五项统计。用该路径校验并恢复到一个新文件：

~~~powershell
& '.\.venv\Scripts\python.exe' -m app.backup verify '备份文件完整路径'
& '.\.venv\Scripts\python.exe' -m app.backup restore '备份文件完整路径' --output 'data/restore-practice.sqlite3'
& '.\.venv\Scripts\python.exe' -m app.backup verify 'data/restore-practice.sqlite3'
~~~

将占位路径替换为实际路径；恢复文件已存在时应改用新文件名，工具不会覆盖。
备份包含全部历史及故障事件，并保留名称、网址、暂停状态和编号序列。
备份可在后端运行时执行，使用 SQLite 快照接口，避免遗漏 WAL 中的已提交记录。
恢复副本与备份的 targets、checks、incidents、paused_targets、last_target_id 应一致。
演练不切换应用数据库；真实替换应另行停止后端并保留当前数据，不能直接覆盖正在运行的数据库。
旧快照不包含备份之后的变化，也会回滚编号分配；关闭旧页面后再使用恢复的服务。
只恢复自己的可信备份，校验不提供真实性证明。同盘副本不能防硬盘损坏，长期备份应另存独立介质。
本轮验证 Windows 本机磁盘，输出位置须支持硬链接；不支持覆盖恢复、自动保留策略或跨版本迁移。

## 排障

- WinError 10048：端口被占用，先检查是否重复启动。
- 无法取得数据库进程锁：核对是否有旧实例仍在运行，保持 --workers 1，不使用热重载。不要删除 data 下的锁文件；正常或异常退出后操作系统会释放锁。若无其他实例，再检查目录权限。
- 页面调度状态读取失败：检查后端是否已重启到新版；先看启动日志中的 Scheduler started 与实际间隔。
- 定时未新增记录：核对暂停状态、间隔、最后一次手动检查或配置修改时间，再点“刷新历史”；查看后端是否出现调度或数据库错误。
- 找不到 app：确认终端处于项目根目录。
- No module named：确认使用项目 .venv 并已安装依赖。
- 配置读取接口 404：可能仍运行旧版后端，重启 8000 服务后刷新。
- 数据库错误：查看后端终端中 SQLite 错误，检查文件权限、磁盘空间和是否有其他进程占用数据库；不要直接删除数据文件。
- “检查已执行，但历史保存失败”：说明目标请求已经进行，结果未确认写入。查看后端日志中的 SQLite 原因；不要把这次请求当成已保存记录。
- 图表组件未加载：先重启 8000 后端，再刷新页面，确认 /response-chart.js 能返回脚本。
- 历史读取失败：页面应提示读取错误，重新选择目标或刷新重试，不代表网站异常。
- 连接失败：核对目标服务、网址和网络；错误本身不能单独确定根因。
- Git 查看记录出现 less 错误：使用 git --no-pager log 或 git --no-pager show。
