# 巡小站

AI 辅助开发的个人学习项目，用于练习 HTTP 服务部署、巡检与故障排查。
当前进度：多目标管理——添加、列出和选择目标，按编号编辑、暂停、检查及删除。

## 当前功能

- 添加多个目标，按编号选择、编辑名称与 HTTP/HTTPS 网址，配置保存到 SQLite。
- 按编号删除目标，页面确认后操作；检查中的目标返回 409，需完成后再删除。
- 删除不会关闭目标网站；新目标不会复用已删除编号，删除全部目标后重启仍为空列表。
- 相同网址经基本规范化后不能重复添加；同名但网址不同的目标用编号区分。
- 重启应用后保留配置和暂停状态；保存、暂停和恢复操作本身不会请求网站。
- 暂停时页面禁用检查按钮，后端也会拒绝直接检查请求。
- 手动检查后显示正常、异常、尚未检查，以及状态码、耗时、时间和错误原因。
- 总时限 10 秒，最多跟随 5 次重定向，最终 200–299 为正常。
- 只读取最终响应头；失败耗时表示等到失败的时间。
- 验证 HTTPS 证书；HTTP 客户端不自动读取系统代理环境变量。
- 异步请求；SQLite 操作在线程中执行。
- 同一进程中，同一目标的检查与修改不能重叠；重叠请求返回 409。不同目标使用独立锁。
- 采用 UTC 传输检查开始时间，页面显示北京时间。

## 当前限制

暂未实现检查历史入库、定时任务、故障事件、响应曲线和鉴权。
目标列表、配置和暂停状态写入数据库；结果按目标编号暂存在当前页面，刷新后清空。
列表中的“尚未检查（本页）”不表示历史上从未检查，而是当前页面还没有该目标的结果。
证书错误目前与其他连接错误归为一类，后续细分并专项测试。
只允许单进程启动；进程间重复启动防护将在定时任务阶段实现。
默认仅监听本机，不能直接暴露公网。只检查你有权访问和检查的目标。
本工具不验证网页正文、登录流程和全部业务功能。

## 文件与职责

- app/main.py：输入校验、FastAPI 接口与 HTTPX 检查。
- app/database.py：SQLite 初始化、旧表增量升级、读取和保存目标及暂停状态。
- app/static/index.html：表单、状态展示、按钮逻辑，无外部前端依赖。
- requirements.txt：已固定的完整依赖版本。
- tests/test_manual_check.py：本机服务和独立临时数据库测试。
- data/xunxiaozhan.sqlite3：首次启动时自动创建的运行数据库，Git 忽略整个 data 目录。

## 环境与首次安装

开发环境为 Windows、Python 3.13.15，其他操作系统尚未验证。
SQLite 使用 Python 自带模块，无需安装数据库软件。已有环境可跳过安装：

~~~powershell
python -m venv .venv
& '.\.venv\Scripts\python.exe' -m pip install -r requirements.txt
~~~

这里的 python 必须是已确认的 Python 3.13；多版本机器建议使用完整路径。

## 启动

在项目根目录打开第一个 PowerShell 窗口，启动被检查的网站：

~~~powershell
& '.\.venv\Scripts\python.exe' -m http.server 8765 --bind 127.0.0.1 --directory app/static
~~~

这里只提供静态文件目录，避免把项目配置和虚拟环境作为网站内容提供。

第二个 PowerShell 窗口进入同一个项目目录，启动巡小站：

~~~powershell
& '.\.venv\Scripts\python.exe' -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
~~~

浏览器打开 http://127.0.0.1:8000/。
8765 是目标网站，8000 是巡小站；操作面板只使用 8000 地址。
两个窗口都保持运行，Ctrl+C 停止对应服务。不使用多 worker 或热重载。
代码更新后，停止并重启 8000 后端，再刷新页面。

## 多目标演练

1. 更新后重启 8000 后端并刷新页面；目标列表应保留原来的名称、网址和暂停状态。
2. 选择原目标，必要时恢复巡检；保持 8765 测试网站运行，手动检查首页，应得到 200。
3. 展开“添加目标”，名称填“本机404测试”，网址填 http://127.0.0.1:8765/missing-demo-page。
4. 添加成功后自动选择新目标，显示它自己的编号，结果为“尚未检查”。
5. 点击检查，应得到 404；这里是目标网站对不存在路径的正常 HTTP 响应，本项目按约定把非 2xx 判为异常。
6. 切回原目标，它仍应显示此前的 200。暂停新目标不应影响原目标。
7. 再次添加相同网址，应收到重复提示，不应多出一条记录。
8. 重启后刷新，两个目标都应保留；本页检查结果会清空。

编辑后有未保存的内容时，先保存或点击“取消修改”，再切换目标。
添加和删除目标都不会请求网站。删除演练见下一节。

## 删除演练

只对专门新增的练习目标操作，保留已有目标。

1. 重启 8000 后端并刷新页面；添加“删除练习”，网址为 http://127.0.0.1:8765/delete-demo。
2. 记下新目标编号。点击“删除目标”，核对确认框中的编号、名称和网址，先取消一次，记录应仍在。
3. 再次点击并确认，只有该目标应消失；选择原目标，仍可按原来的方式检查。
4. 用相同名称和网址重新添加，新编号应大于刚才删除的编号。

删除是移除数据库中的配置，暂停是保留配置并暂时不检查。
删除没有撤销入口；重新添加会分配新编号。当前版本尚无数据库检查历史。
删除最后一条后显示空状态，可重新添加；重启不会补回演示目标。
旧浏览器页面访问已删除编号会返回 404，请刷新列表；网络中断时先刷新核对是否已删除，再决定是否重试。
首次启动新版时，自动增加编号记录表，保留已有目标；编号记录不能随意清空。
仍只支持单进程，不能同时用旧代码写入同一数据库。

## 当前接口

接口已从单目标形式改为带编号的形式；旧版 /api/target 和 /api/check 不再使用。
历史阶段文档保留旧接口作为当时的学习记录，当前操作以本节为准。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | /api/targets | 读取所有目标 |
| POST | /api/targets | 添加一个目标，成功返回 201 |
| GET | /api/targets/{id} | 读取指定目标 |
| PUT | /api/targets/{id} | 保存指定目标的名称和网址 |
| DELETE | /api/targets/{id} | 删除指定目标，成功返回 200 和 deleted_id |
| PATCH | /api/targets/{id}/state | 暂停或恢复指定目标 |
| POST | /api/targets/{id}/check | 检查指定目标 |

不存在的编号返回 404，不会回退为检查第一个目标。
重复网址、暂停或同目标操作冲突返回 409；无效输入返回 422。
上述状态码是巡小站接口响应；目标网站自身的 HTTP 状态码在检查结果字段中。

## 目标配置与重启演练

1. 将名称改成“我的本机练习站”，保留 http://127.0.0.1:8765/。
2. 点击“保存配置”。页面提示保存成功后，点击“立即检查”。
3. 停止 8000 后端并重新启动，刷新浏览器；名称和网址应仍保留。
4. 检查结果回到“尚未检查”属于当前版本预期，因为尚未保存检查历史。
5. 网址修改为 ftp://127.0.0.1:8765/ 后尝试保存，应提示无效；
   刷新页面后应读到之前保存的 HTTP 网址。
6. 同一个目标检查中不能修改配置；多窗口操作若收到 409，等检查完成再试。

名称限 1–80 字，网址限 2048 字符，只支持 HTTP/HTTPS，
不接受账号密码、空白或 # 片段。格式有效不代表网站一定能访问。

## 暂停与恢复演练

1. 重启 8000 后端并刷新页面，确认原来的名称和网址还在。
2. 点击“暂停巡检”，应显示“已暂停”，检查按钮禁用；目标网站本身不会被关闭。
3. 暂停后重启 8000 后端并刷新，暂停状态应保留。
4. 点击“恢复巡检”，只是重新允许检查；再手动检查才能获得新的目标状态。
5. 检查进行中不能暂停，接口返回 409，等待完成后重试；本轮不取消在途请求。
6. 暂停期间可以保存名称和网址，保存不会自动恢复巡检。

暂停表示主动不检查，不等于目标正常或异常。
下方保留的结果若未刷新，仍只代表之前那次检查。
重启时自动为旧表添加 paused 字段，保留名称和网址，不要求删除数据库。
多进程并发升级尚不支持，请保持单进程运行。

## 故障演练

1. 两个服务均运行，点击检查，应正常、HTTP 200。
2. 仅停止 8765 服务，再检查，应异常且没有 HTTP 状态码。
3. 重启 8765 服务，再检查，应恢复正常。
4. 停止 8000 后端则按钮无法获取新结果，与目标网站异常不同。
5. /api/health 返回 ok 只说明巡小站接口可响应，不证明目标或数据库健康。

## 排障

- WinError 10048：端口被占用，先检查是否重复启动。
- 找不到 app：确认终端处于项目根目录。
- No module named：确认使用项目 .venv 并已安装依赖。
- 配置读取接口 404：可能仍运行旧版后端，重启 8000 服务后刷新。
- 数据库错误：查看后端终端中 SQLite 错误，检查文件权限、磁盘空间和是否有其他进程占用数据库；不要直接删除数据文件。
- 连接失败：核对目标服务、网址和网络；错误本身不能单独确定根因。
- Git 查看记录出现 less 错误：使用 git --no-pager log 或 git --no-pager show。
